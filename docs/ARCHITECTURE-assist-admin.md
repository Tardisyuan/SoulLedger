# 助手管理页(阶段 1.5)—— 计划稿

> **状态:§7 Q1–Q3 已由用户拍板(2026-09-29);Q4 等 Design 出稿。** 用户 2026-09-29 定:阶段 1.5 不由开发者拿 key 在后台跑评测,
> 而是给**管理员一个页面**,在页面上完成配置与测试。**整个系统只有一位管理员**(ADMIN,阎罗王),
> 所以这一页只对 ADMIN 开放,不做多人协作、不做审批。
> 灵魂端与官员端助手的设计见 `docs/ARCHITECTURE-soul-assist.md`、`docs/ARCHITECTURE-officer-assist.md`。

## 1. 为什么要搬到页面上

现在所有配置都是环境变量(`backend/config/settings.py:431-447`):换供应商、换模型、开关都要改部署再重启,
而评测只能由开发者带着 key 在本机跑。管理员是唯一会决定「用哪家、花多少钱、开给哪些殿」的人,
这些决定应该在他能看见结果的地方做。

## 2. 配置项:哪些上页面,哪些不上

| 配置 | 现在 | 上页面? | 说明 |
|---|---|---|---|
| 总开关 `ASSISTANT_ENABLED` | env | **上**(运行时开关) | env 仍是**硬上限**:env 为假时页面开关无效,并在页面上说明原因 —— 部署方保留一票否决 |
| 每殿开关 `Tenant.settings["assistant_enabled"]` | 只能改库 | **上** | 一张殿列表,每行一个开关;显示「原属该殿的灵魂数」 |
| 灵魂端 / 官员端分别开关 | 无 | **不拆** | 维持官员端计划 Q3 的决定:共用一个开关(§7 Q3) |
| 供应商类型(OpenAI 兼容 / Anthropic) | env | **上** | 下拉 |
| Base URL | env | **上** | Azure / Ollama / DeepSeek 等填这里;Anthropic 留空 |
| API key | env | **上,只写不读** | 加密存库(复用 `apps/death_sync/fields.py` 的 Fernet,`ENCRYPTION_KEY`);页面只显示「已设置 · 末 4 位 · 设置于某日」,可替换、可清除,永不回显 |
| 模型名 | env | **上** | 自由填写 + 常用项提示;保存前必须先通过 §3 的连通测试 |
| effort(Anthropic) | env | **上** | low / medium / high,附成本说明 |
| 拒答回退 fallbacks(Anthropic) | env | **上** | 开 / 关 |
| 每账号每小时次数(30) | settings 常量 | **上** | 灵魂端、官员端各一个数 |
| 全局并发上限(8) | env | 只读显示 | 受 PG 连接数约束,改错会拖垮全站;改它是部署的事 |
| 总超时(22 秒) | env | 只读显示 | 必须小于 App 的 25 秒,页面改不安全 |
| 历史条数(20) | env | 只读显示 | 与成本有关但不常改 |
| 原文留存天数(30) | 代码常量 | 只读显示 | 已对灵魂公示(首次说明、帮助条目),改它要连公示一起改 |
| 月度花费上限 | 无 | **新增,上页面** | 按 token 用量估算;到上限自动关掉总开关并通知管理员(见 §7 Q2) |

**生效规则:** 库里的值覆盖 env,env 是初始值与硬上限(只对总开关)。每次保存写一条审计(`resource="assistant_config"`),
记改了哪些键、旧值与新值 —— **API key 只记「已更换」,不记值**。

## 3. 测试

**3.1 连通测试。** 用待保存的配置发一条最小请求,显示:成功 / 失败原因(鉴权、模型不存在、超时、
不支持工具调用)、延迟、token 数。模型名改动**必须先通过这一项才能保存**。

**3.2 评测集。** 页面上跑一组固定问题(≥20 条,灵魂端与官员端各一组),每条:期望调用的工具、
回答里必须包含 / 不得包含的要点。结果逐条显示:实际调用的工具、回答原文、判定、延迟、token;
汇总:工具调用正确率、要点命中率、平均延迟、估算花费。
- 可以**对比两套配置**(例如当前模型 vs 待换模型)并排跑,不必先保存。
- 每次运行真的花钱:开始前显示「约 N 条请求、预计花费」,确认后才跑;跑的记录保存,可回看。
- 评测跑在后台任务里,页面轮询进度;单次运行有总条数与总花费上限。
- 评测用专门的测试身份:灵魂端用一个评测灵魂(可以沿用 115 上的 `NEB6M2YD87` 那一类),官员端用一个评测官员,
  数据范围照正式规则走,不开后门。

**3.3 试问。** 一个输入框,以指定的测试身份问一句,看回答与工具调用。用于调提示词前后的手感,不计入统计。

## 4. 用量与质量(管理员的「实际用量」页)

- **单独一页**给管理员看实际用量(用户 2026-09-29 明确要求):本月已花 / 上限、按天、按殿、按灵魂端 / 官员端的问答数、token、估算花费(来自 `AssistMessage.tokens` 与审计行)。
- 失败率:503 不可用、429 限流、空回答(「答不了」固定回复)各自的占比。
- **阶段 4 的触发指标**直接显示:帮助语料 token 数(阈值 8 万)、「答不了」占比(阈值 15%)。
  到阈值时页面给出提示,决定仍由人做。

## 5. 帮助语料

只读展示:条目列表(按受众、页面、文明筛选)、每条的中英文、总 token 数。语料仍以仓库文件为准、走代码审查,
**页面不改语料** —— 改语料等于改助手说的话,应当留痕在 git 里,而且防漂移测试只在仓库上跑。

## 6. 实现要点

- 新表 `AssistConfig`(单行)与 `AssistEvalRun` / `AssistEvalCase`;`get_provider()` 改为读库配置
  (进程内缓存,保存时失效);env 仍作初始值。
- 接口在 `/api/v1/assist-admin/`,官员令牌 + **只许 ADMIN**(`role == "ADMIN"`,不走可授予的权限码,
  以免被「权限」页误授给别人)。
- 前端新页面(路由待 Design 定),需要 Design 出稿。
- 门禁:配置保存的审计不含 key(断言缺席);非 ADMIN 403(含 MODERATOR);env 总开关为假时页面开关无效;
  key 在库里是密文(直接查表断言不含明文);评测不绕过数据范围。
