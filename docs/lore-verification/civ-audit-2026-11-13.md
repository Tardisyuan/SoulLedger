#### 另核:官员 App(`mobile-officer/`)能否判希腊的「普通」(PURGATORY)

**结论:不能。而且不是希腊特有 —— 官员 App 对任何文明都只能落 PASSED 或 FAILED。**

证据(判案流程读完):

- 整个 `mobile-officer/src` 里 `judgmentApi.conclude` 只有一处:`decisions.ts:75-77` 的 `submitVerdict`;它唯一的调用方是 `screens/swipe.tsx:154`(`send`)。
- `send` 收到的 payload 只有三个来源:`swipe.tsx:178` `passPayload(current.civilization)`、`:410` `AccountSheet` 的 `passPayload("GREEK", account)`、`screens/rejectSheet.tsx:252` `failPayload(civ, choice)`。`verdict.ts:71-83` 这两个函数的 `verdict` 字面量只有 `"FAILED"` / `"PASSED"`。`swipe.tsx:152` 的飞出方向也只分 PASSED / 其他。
- 滑卡的第三个手势是「待定」:`swipe.tsx:220,415-425` 调 `judgmentApi.defer`(放进待定、停表),不是裁决,不产生 PURGATORY / RETRY。
- 详情页的动作(`screens/judgmentActions.tsx:208-336`)只有 release / defer / undefer / requestReassign / reassign,没有 conclude。
- `decisions.ts:48-49` 的 `approveNode` 是审批流程节点(待办),发的是 `PASSED` / `CONFIRMED` / `REJECTED` / `FAILED`(`rules.ts:124-143`),不是结原审。
- grep `PURGATORY` 在 `mobile-officer/src` 非测试代码里只有 `soulDetail.tsx:341` 一处,是**显示**历史裁决名。

所以希腊的普通亡灵(去阿斯福得草原)、欧洲的炼狱、以及各文明的 RETRY,都只能在 web 审判台判;手机上希腊案子只有「至福岛 / 塔尔塔罗斯」两条路。这与 web(四个裁决、默认 PURGATORY)是端与端不一致,但它是 v4 S09 滑卡「左不过 / 右通过」的设计范围,2026-11-11 加三分后没有跟上;严重度建议**低到中**(功能缺口,不会写错数据)。未在设备上跑。
