## 0. 一句话结论

**《太微仙君功過格》（1171）的全文拿到了，75 条一条不缺，分值逐条可核，结算规则有两段原文。** 这是本次调查里最干净的一次取证——不像埃及 42 判官和中国冥律，这份文本有明确的作者、年代、道藏卷次、两个独立数字转录本，且被西方学界（Brokaw 1991）确认为现存最早的功过格。

**但有一个必须写进数据里的性质问题：功过格是「在世者的自记账簿」，不是冥官判案用的法典。** 它甚至不以死后审判为主要赏罚机制——它的原生赏罚是**在世减寿**（奪紀奪算）和**积善成仙的阈值**（三百善地仙 / 一千三百善天仙），不是打入哪一层地狱。项目若拿它做审判依据，那是一次**有意的挪用**，必须在数据里注明。

**衰减机制：功过格没有衰减，一点都没有。** 它有的是**周期结算 + 余额结转**（一月一小比、一年一大比），以及**非同质抵扣规则**（《文昌帝君功過格》明文规定百功的钱财不能抵一条人命的百过）。这三样和 `LedgerService` 的指数衰减是三种不同的机制。**判断：不该混用。** 详见 §6。

### 1.1 两个独立转录本的交叉核对（研究纪律）

我取得了**两个互相独立的数字转录本**并逐字比对：

- **A**：维基文库 `zh.wikisource.org/zh-hans/太微仙君功過格`（标注 from=正統道藏，TextQuality 75%）
- **B**：中國哲學書電子化計劃 ctext.org `chapter=199527`

**结论：结构完全一致，条目顺序完全一致，绝大多数分值完全一致。** B 本有明显 OCR 噪声（`兔`←免、`竭`←蝎、`飲鳝`←飲膳、`執帛`←紈帛、`租先`←祖先、`誠勸`←誡勸、`士一條`←十二條、`過向`←迴向、`＋過`←十過）。**差异中只有 3 处是实质性的**：

| 处 | A（维基文库） | B（ctext） | 判断 |
|---|---|---|---|
| 救濟門#4 | 「**滅**死刑性命一人為五十功」「**滅**人徒刑」「**滅**人杖刑」「**滅**人笞刑」 | 「**減**死刑…」「**減**人徒刑」… | **B 对**。「救／免／減」三级递降（救他人主办的案 / 自己主办而原免 / 减轻刑等）语义自洽，「滅」为形近讹字。A 为转录错误 |
| 用事門#6、#10 | 「勸**謙**人鬪爭」「勸**謙**人令不為非…」 | 「勸**諫**人鬪爭」「勸**諫**人令不為非…」 | **B 对**。「勸諫」是词，「勸謙」不是 |
| 不仁門#4 尾 | 「為行法官，妄入**罪**者，亦同此論」 | 「為行法官，妄入**鬼神罪**者，亦同此論」 | **B 多「鬼神」二字**。若 B 对，这句是说**行法道士妄劾鬼神之罪**也照此论过——对本项目有意思（这是全文唯一涉及「对鬼神定罪」的一句）。**未能定谳，需影印本** |

**⚠️ 我没有核对道藏影印本。** 两个转录本都是数字文本，同源于道藏本的可能性存在（虽然 OCR 特征不同，倾向于独立录入）。上表的判断是基于文义的校勘意见，不是版本学结论。

## 4. 结算规则（原文两段）

### 4.1 序文（宏观规则）

> 著斯功格三十六條、過律三十九條，各分四門，以明功過之數，付修真之士**明書日月，自記功過，一月一小比，一年一大比**，自知功過多寡，**與上天真司考校之數，昭然相契，悉無異焉**。大凡一日之終，**書功下筆乃易，書過下筆的難**。

### 4.2 「凡受持之道」（操作规程 — 这才是可实现的那段）

> 凡受持之道，常於寢室床首，置筆硯簿籍，**先書月分，次書日數，於日下開功過兩行**，至臨卧之時，記終日所為善惡，照此功過格內名色數目，有善則功下注，有惡則過下注之，**不得明功隱過**。**至月終計功過之總數，功過相比，或以過除功，或以功折過，折除之外者，明見功過之數，當書總記訖，再書後月，至一年則大比，自知罪福，不必問乎休咎。**

**拆解成机制**：

| 环节 | 原文 | 机制 |
|---|---|---|
| 记录粒度 | 「先書月分，次書日數，於日下開功過兩行」 | **按日双栏记账**（借贷两行），不是单一净值 |
| 记录时点 | 「至臨卧之時，記終日所為善惡」 | 每日睡前一次批量登记 |
| 诚信约束 | 「不得明功隱過」 | 自记账簿的**唯一防作弊条款**——靠自律，无外部审计 |
| 月结 | 「至月終計功過之總數，功過相比，或以過除功，或以功折過」 | **月末净额结算**，双向抵消 |
| 结转 | 「折除之外者，明見功過之數，當書總記訖，再書後月」 | **余额结转下月**，不清零、不衰减 |
| 年结 | 「至一年則大比，自知罪福」 | 年度大结算 |
| 目的 | 「不必問乎休咎」 | 结果**自明**，不需要占卜或外部裁决 |
| 心理设计 | 「書功下筆乃易，書過下筆的難」 | 作者自己承认记过比记功难——这是**认知偏差的自觉** |

**「一月一小比，一年一大比」＝周期净额结算 + 余额结转。不是衰减，不是清零。**

### 5.3 差异有多大？——量化回答

1. **规模**：75 條（1171）→ 1281 格（1724）。**扩张 17 倍。**
2. **分类轴**：**完全重构过三次**。太微是道士仪轨轴 → 自知錄换成佛教三宝轴 → 文昌换成儒家伦常/仕宦轴 → 十戒换成佛教十戒轴。**四本没有一个共享分类体系。**
3. **分值**：**部分锚点极其稳定，其余全变**。
   - 稳定：救人一命 **100 功**（太微 → 文昌，跨 553 年不变）；賑貧 **百錢一功**（同上）；救重疾 **10 功**／小疾 **5 功**（太微 → 自知錄，逐字不改）
   - 剧变：救危症 10 → 50（十戒）；金钱换算 100 錢/功 → 30 文/功（十戒）；上限 100 → 1000（文昌）
4. **结算规则**：**这是最稳定的部分**，四本几乎同构（见 §5.4）。

### 5.4 结算规则的跨本延续（原文对照）

| 本 | 原文 |
|---|---|
| **太微（1171）** | 「明書日月，自記功過，**一月一小比，一年一大比**」／「至月終計功過之總數，功過相比，或以過除功，或以功折過…**自知罪福，不必問乎休咎**」 |
| **自知錄（明末）** | 「**積日而月，積月而年，或以功准過，或以過准功，多寡相讎，自知罪福**」 |
| **文昌（1724）** | 「臨臥時，憶一日所為，依格詳註…**不得明功隱過**，不得輕忽作輟。**月終合計總數，功過相比，或以過除功或以功折過。折除之外註明功過實數，年終總結，多寡相較，便可自知罪福。不必更問休咎**」 |

**《文昌帝君功過格》的凡例与《太微》的「凡受持之道」几乎逐字相同**（「不得明功隱過」「或以過除功或以功折過」「折除之外」「自知罪福」「不必更問休咎」全部照搬）。这证明：**条目和分值可以整个换掉，结算规则不能。** 对项目的启示见 §7。

**另注**：**《自知錄》的书名即出自《太微》的结算句「自知罪福」**。

### 5.5 ⚠️ 书名撞车警告

《佛學大辭典》「自知錄」条指的是**另一本书**：「（書名）一卷，**元中峰**著。附於**三時繫念**之後。」——元代中峰明本的《自知錄》，与袾宏的功过格本《自知錄》同名异书。**项目若引用《自知錄》，必须写全「明·雲棲袾宏《自知錄》」。**

## 6. 性质问题：自我记录 vs 冥官审判（**关键节**）

### 6.1 功过格的原生赏罚不是死后审判

**这是必须写进数据的一条。** 功过格所属的那个赏罚体系，其制裁手段是：

**(a) 在世减寿（奪紀／奪算）** — 这是主要制裁。

《太上感應篇》（一手，維基文庫）：
> 是以**天地有司過之神**，依人所犯輕重，**以奪人算**。算減則貧耗，多逢憂患…**算盡則死**。又有三台、北斗神君，在人頭上，**錄人罪惡，奪其紀算**。又有**三尸神**，在人身中，**每到庚申日，輒上詣天曹，言人罪過**。**月晦之日，竈神亦然**。凡人有過，**大則奪紀，小則奪算**。

其源头见《抱朴子·微旨》（晉·葛洪，一手，維基文庫）：
> 天地有司過之神，隨人所犯輕重，以奪其算…是以每到庚申之日，輒上天白司命，道人所為過失。又月晦之夜，灶神亦上天白人罪狀。**大者奪紀。紀者，三百日也。小者奪算。算者，三日也。**〔葛洪自注：**吾亦未能審此事之有無也**〕

- **紀＝300 日，算＝3 日**（葛洪原文明确定义）。
  ⚠️ 后世《感應篇》注疏传统常作「紀＝12 年、算＝100 日」，**我没有取得可靠出处，不采用**。若项目要用，必须另查。
- 葛洪本人加了一句「我也没法确定这事有没有」——**四世纪的作者就对这套机制存疑**，值得作为 source_note 保留。

**(b) 成仙阈值（累计达标）** — 这是主要奖励。

《太上感應篇》：
> 欲求**天仙**者，當立**一千三百善**；欲求**地仙**者，當立**三百善**。

**(c) 余庆余殃（转移到子孙）**

《太微仙君功過格》序开篇即引《易》：
> 《易》曰：**積善之家，必有餘慶；積不善之家，必有餘殃。**

**这三条制裁全部作用于「阳间」——寿命、成仙、子孙。没有一条是「判入某殿某狱」。** 功过格的世界里，你的分数决定的是**你还能活多久、能不能成仙、你儿子过得好不好**，不是你死后被押到第几殿。

### 6.2 但它确实自称与「天上的账」对应——而且后世越挂越紧

这是必须说清的另一半。功过格**不是**纯粹的世俗自我管理工具，它一直声称自己是**天曹账簿的副本**：

**《太微》序（1171）**：
> 自記功過，一月一小比，一年一大比，自知功過多寡，**與上天真司考校之數，昭然相契，悉無異焉**。

——「你自己算出来的数，和上天真司考核出来的数，分毫不差。」**这是功过格的核心宗教主张：自记账簿是天曹底账的镜像。**

**《文昌帝君功過格》序（1724）**：
> 則善惡之念慮一萌，**神鬼早已洞見肺腑**，不可懼歟？

**《十戒功過格》序（清）**——走得最远，直接把功过格等同于**陰律**：
> **陽律多論跡所以甚疎。陰律惟論心所以甚密。**…欲起實心袪妄念，**必考核於陰律。知陰律之重輕，然後知立心之誠偽**…夫所謂**陰律**者，合三為一以定果報者也。三者何？**身業語業意業**是也…**東岳掌鐵律以治鬼**，鬼業惟惡，惡業之中例分三等以定三途…**上清掌玉律以治仙**，仙業惟善…

> 〔不軌門乩訓〕一人造殺器，千人之殺皆因之，故**陰律獨重**。

——清代的《十戒功過格》明确说：功过格是**陰律的可读版本**；真正的律在東岳（鐵律治鬼）和上清（玉律治仙）手里，功过格是给凡人对照用的换算表。

**⚠️ 但注意**：「陰律」在这里仍然是**观念范畴**（因果之律），**不是一部有编号条文的法典**。这与 `verify-cn-structure.md` §2.1(d2) 的结论一致——**不存在题名《冥律》且含编号条文的传世文本**。《十戒功過格》说的「東岳鐵律」「上清玉律」是**神职分工的说法，没有给出任何条文**。

### 6.3 结论：功过格能不能当审判依据用？

**能，但必须显式标注为挪用，且标注内容要准确。** 分三层说：

| 层 | 判断 |
|---|---|
| **「功过格是一部冥律法典」** | ❌ **假**。它是**在世者的自记道德账簿**，一卷，托梦降授，收在道藏**戒律類**——是**戒律**（给活人守的），不是判牍 |
| **「功过格的分数被冥官用来判案」** | ⚠️ **无直接依据**。没有任何一本功过格描述冥官翻阅功过格判案的场景。它的制裁是**减寿/成仙/余殃** |
| **「功过格的分数与天曹的账一致」** | ✅ **有原文依据，且是核心主张**。《太微》序「與上天真司考校之數，昭然相契，悉無異焉」；《十戒》序把它挂到「陰律」 |

**所以项目可以诚实地这样说**（这个措辞有一手依据，不需要编造）：

> 本系统的中国侧计分体系锚定于《太微仙君功過格》（1171）。原文本是**在世修道者每日自记的道德账簿**，其原生赏罚为在世减寿（奪紀奪算）、成仙阈值与子孙余庆，**并非冥府判案所依据的法典**。本系统将其用作审判计分依据，是一次**有意的挪用**，其唯一文本依据是该书序文的主张——自记之数「與上天真司考校之數，昭然相契，悉無異焉」，即账簿被视为天曹底账的镜像。清代《十戒功過格》序进一步将功过格挂靠于「陰律」，但同样未提供任何编号条文。

**这段话每一句都能落到原文上。** 而且它比原来那份假冥律**更有戏剧性**——「你自己记的账，就是天上那本账」是个比「有一部十三条的冥律」好得多的设定。

### 6.4 与《玉历宝钞》的关系：两个体系，不要缝合

- **《玉历宝钞》**（清善书）：**逐殿叙述体**，罪目 → 地狱对应，**没有分值**。
- **《功过格》**（1171 起）：**条目 + 数值**，**没有地狱**（太微全文不出现任何地狱名）。

**两者在传统中是并行的两类善书，没有哪个文本把它们合起来用。** 项目现有的 realm 结构（十殿）来自《玉历》一系，计分系统来自功过格一系——**这个组合本身是项目的合成，不是传统。** 建议在数据里注明，而不是让 `HELL_LAW` 这个 corpus 名同时暗示两者。

## 7. 与本项目 `LedgerService` 的契合度

### 7.1 现有机制回顾

`backend/apps/ledger/services.py`：
- `DECAY_RATE = 0.01`/年，指数衰减 `effective = original × e^(-rate×years)`
- `CIVILIZATION_DECAY_RATE`：中国 0.01、埃及 0.01、欧洲 0.0
- 锚点为**死亡日**（`_get_decay_anchor`），即「生命末端的视角」，晚年行为权重高于早年
- `INHERITANCE_MERIT = 0.2`（功德转世递减）；恶业不递减

**先说一件对的事**：`services.py` 第 31–41 行的注释**已经把这个问题答对了**：

> 「Strictly, *no* tradition surveyed here attenuates a deed by elapsed time: **功過格 is cumulative and its entries do not expire**… Decay survives everywhere else in this table as a *product* choice… It is not a thing any of these cosmologies asserts.」

**这段注释与我的独立查证完全一致。** 本节不推翻它，只是给它补上一手依据，并指出功过格另外提供了三样**可以真正落地**的机制。

### 7.2 逐项判断

| 机制 | 功过格有没有 | 与项目的关系 | 判断 |
|---|---|---|---|
| **时间指数衰减** | ❌ **完全没有**。75 条中无一条与「过了多久」有关。月结的余额「當書總記訖，再書後月」——**原样结转，不打折** | 项目的 `DECAY_RATE` 无对应 | **不该混用**。保持现状（标为产品选择），**不要**把衰减重新挂到功过格头上。那会是本次调查最不该犯的错 |
| **周期结算（一月一小比／一年一大比）** | ✅ **有，且是四本共通的最稳定部分** | 项目**没有**周期结算，是连续实时衰减 | **需要适配**。可作为**呈现层**（月度/年度对账单）落地，**不要**做成额外的算术操作——那会与衰减双重计算 |
| **功过相抵（净额）** | ✅ **有明确算术定义**：「一過去功一分，十過去功十分」（不善門#8 夹注） | 项目已有 merit/demerit 净额 | **直接对应** ✅ |
| **非同质抵扣（不可折）** | ✅ **有，且是硬规则**（见下） | 项目**没有**——单一标量池，任何功抵任何过 | **重大缺口**，见 §7.3 |
| **单次行为上限** | ✅ 一处（「人數雖多，止五十功」） | 项目无 | 可选 |
| **累计阈值（300善地仙／1300善天仙／3000善）** | ✅ 有，且是原生的奖励机制 | 项目有 `disposition` 判定，机制类似 | **直接对应** ✅ — 阈值制比衰减制更贴功过格 |
| **金钱换算率（百錢＝一功）** | ✅ 有，且**各本不同**（太微 100 錢/功；十戒 30 文/功） | 项目无 | 若要落地，**必须绑定版本** |
| **半功/半过（非整数）** | ✅ 有（0.5） | 项目 `merit_points` 若为整数则**存不下** | **需要字段变更** |
| **派生分值**（「隨本人之過減半」） | ✅ 有 | 项目无 | 需 payload 支持 |

### 7.3 最重要的一条：**功过不可自由抵扣**

《文昌帝君功過格·凡例》（雍正二年，一手，維基文庫）：

> **功過有不可折者。如用財之百功，不可折致死人之百過。零積之十功不能折一次之十過也。**

两条硬规则：
1. **跨类不可抵**：花钱积的 100 功，**不能**抵一条人命的 100 过。
2. **零积不抵整发**：十次小善攒的 10 功，**不能**抵一次性的 10 过。

**这直接否定了「单一标量池 + 净额」这个模型。** 项目当前 `LedgerService` 就是单一标量池——一个人捐够钱就能把杀人抵掉。**这在功过格传统里是被明文禁止的。**

同一凡例还给了**倍率规则**：
> 功過加增，有分載格中者，如**救人一命一百功，賑貧百錢一功**，若救人一命複用己之財，則於百功外更照百錢記一功。

即：**一个行为可以同时命中多个条目并叠加**（救人一命 100 功 + 自掏的钱另按百錢一功计）。

**这是本次调查对项目最有价值的发现**：功过格提供了一个比「加权求和 + 衰减」**更有内容、且完全有出处**的记账模型。

## 8. 落地建议

### 8.1 corpus 层

`StatuteCorpus.HELL_LAW`（「冥律 — Hell Law」）**这个名字是错的**，理由见 `verify-cn-structure.md`。建议：

```
GONGGUOGE = "GONGGUOGE", "功過格 — Ledger of Merit and Demerit (Chinese)"
```

`models.py` 第 135–137 行对 HELL_LAW 的描述（「prescriptive statute — an offence, the hell it lands you in… It is the only one of the three that is written as law」）在改锚后**必须重写**：功过格**不是** written as law，是 self-audit ledger；它**不给地狱**（太微全文无地狱名）。

### 8.2 `Statute` 模型够不够用？——**基本够，缺三样**

| 现有字段 | 对功过格是否够用 |
|---|---|
| `code` | ✅ 建议 `CN-GGG-F-JJ-01`（功格·救濟門·第1条）/ `CN-GGG-G-BR-01`（過律·不仁門·第1条） |
| `ordinal` | ✅ 门内序号 |
| `polarity` | ✅ MERIT / OFFENCE 正好对应 功／過。**不需要新增** |
| `title_zh/text_zh` | ✅ 条目原文可直接入 `text_zh` |
| `source` | ✅ 「《太微仙君功過格》，正統道藏洞真部戒律類雨字號，金大定十一年（1171）又玄子序。維基文庫／ctext 转录，异文见 source_notes」 |
| `source_notes` | ✅ 用来装 §1.1 的异文、§2.1/§3.4 的条数不符 |
| `payload_json` | ⚠️ 得装下复杂结构，见下 |
| **缺 1：门类字段** | ❌ 功过格是**两级分类**（功/過 × 四門）。现在只有 `polarity` 一级。建议 `payload.gate = "救濟門"`，或加 `section` 字段 |
| **缺 2：非整数与多值分值** | ❌ 一个「条」通常含**多个带条件的分值**（救濟門#4 一条 12 个数值），且有 0.5。`payload.merit_points: int` 装不下 |
| **缺 3：抵扣类别（fungibility class）** | ❌ §7.3 的「不可折」规则需要一个类别标记才能实现 |

### 8.3 建议的 `payload_json` 形状

```jsonc
{
  "gate": "救濟門",                 // 四门之一
  "gate_en": "Relief and Rescue",
  "unit": "功",                     // 功 / 過
  "clauses": [                      // 一条内的多个计分子句
    {"condition_zh": "救一人刑死性命", "points": 100},
    {"condition_zh": "免死刑性命一人", "points": 100},
    {"condition_zh": "減死刑性命一人", "points": 50},
    {"condition_zh": "救人徒刑",       "points": 40}
    // …
  ],
  "nullifiers": [                   // 「則無功」条款 — 功过格的特色
    {"condition_zh": "受病家賄賂", "effect": "no_merit"},
    {"condition_zh": "依法定罪",   "effect": "no_merit"}
  ],
  "cap": null,                      // 用事門#2 为 50
  "derived": null,                  // 不仁門#9 为 {"of": "actor_offence", "factor": 0.5}
  "fungibility_class": "LIFE",      // MONEY / LIFE / RITUAL / SPEECH …  见 §7.3
  "money_rate": {"per": 100, "currency_zh": "錢", "points": 1}  // 版本相关
}
```

**`nullifiers` 值得单独说**：功过格有大量「如受賄則無功」「若受法信則無功」——**动机取消功德**。这是原文里反复出现的机制（教典門 4 处、焚修門 3 处、救濟門 3 处），比分值本身更有性格，且项目现在完全没有。

### 8.4 分值真实性的诚实标注

**seed 里绝不能再出现「+100 孝养父母」这种没出处的数字。** 建议：

- 凡直接抄自《太微》的分值 → `source_notes` 写「分值为《太微仙君功過格》原文数值」
- 凡本系统自定的分值 → **必须**写「本系统自定，古籍无此数值」
- 建议给 `Statute` 加 `attestation` 字段（`PRIMARY` / `SECONDARY` / `SELF_AUTHORED`）——这是 `verify-cn-structure.md` §7 优先级 1 第 5 条已经提过的建议，功过格改锚是落地它的好时机

### 8.5 `LedgerService` 的建议

1. **不要**把 `DECAY_RATE` 说成有功过格依据。保持第 31–41 行注释的现有措辞（它是对的），可以补一句一手引证：「《太微仙君功過格》月结原文作『折除之外者…當書總記訖，再書後月』——余额原样结转，无折扣」。
2. **可以加**的是月度/年度**对账视图**（「一月一小比，一年一大比」），作为**呈现层**，不改变底层算术。这有原文依据且是四本共通的最稳部分。
3. **值得认真考虑**的是 `fungibility_class`：§7.3 的「不可折」是硬规则，且它比衰减**更能表达功过格的道德立场**——钱买不到命。如果只能实现一条，实现这条。
4. `INHERITANCE_MERIT = 0.2`（转世递减）**在功过格里没有对应**——功过格没有轮回机制，它的余额去向是子孙（余庆余殃），不是来世。若要保留，标为产品选择。
