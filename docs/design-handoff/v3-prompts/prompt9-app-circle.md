# 给 Claude Design 的 prompt ⑨:灵魂簿 App · 朋友圈(Shemsu)

请在项目「灵魂簿」里新开画布 `灵魂簿 App · 朋友圈.dc.html`,为灵魂端 App 设计**朋友圈**。视觉语言、字体、暗色主题、各文明 ink 配色、底部四个标签(本世 / 前世 / 转生 / 书信)、徽章与分区样式、落地高亮一律沿用 `灵魂簿 App.dc.html`、`灵魂簿 App · 聊天.dc.html`;iOS 与 Android 各出关键屏(差别只在行为，圆角一律 0,关闭 Material 涟漪与阴影 —— 与书信画布一致)。

## 背景(后端已上线，按真实能力设计)

灵魂在本文明里有一个朋友圈:发帖、评论、表态、关注。后端接口(灵魂侧 `/me/social/`):状态、信息流、帖子详情、评论、表态、搜索(本文明内，按显示名或完整灵魂编号精确查找)、关注 / 被关注列表、**他人主页**、关注 / 取关、举报。

- **可见性四档**(发帖时选):公开 PUBLIC · 本文明 TENANT · 仅关注者 FOLLOWERS · 仅自己 PRIVATE(egy 已定稿为 `Wa-Ek`)。
- **表态五种**:LIKE · LOVE · RESPECT · SYMPATHY · ETERNAL_LIGHT(长明灯 —— 逝者语境下最重的一种，请给它独特的呈现)。
- **审核**:含敏感词的帖子进入「待审」,只有作者自己看得到并标明;被隐藏的内容作者看得到「已隐藏」,别人看不到;作者被禁言时不能发帖和评论(书信里写给殿司仍可以)。
- **举报**:帖子、评论、用户都能举报;原因五种:垃圾信息、辱骂骚扰、色情内容、违法有害、其他。
- **前世账号**:转世后，前世的朋友圈账号停用 —— 别人看它的主页、帖子要有「已转世 · 此世已止」的样子，不能再关注。
- **名片白名单**:别人的主页不显示灵魂编号、不显示内部 id。
- 朋友圈只在**当前所在文明**内:暂居的灵魂看到的是暂居地的朋友圈(用户已定：不扩大搜索范围)。

## 需要设计的屏与状态

1. **入口**:朋友圈放在哪(第五个标签会挤;放在「本世」页?书信页顶部切换?)。请给建议并画出，说明取舍。
2. **信息流**:帖子卡片(作者、时间、可见性标记、正文、表态汇总、评论数);空状态;加载与失败。
3. **发帖**:正文、可见性选择(四档要讲清谁能看到);提交后进入「待审」的样子。
4. **帖子详情与评论**:评论列表、写评论、禁言时的锁定态(沿用书信的虚线说明 + 等宽时间)。
5. **表态**:五种的选择与展示,ETERNAL_LIGHT 的特别呈现。
6. **他人主页**:显示名、头像、关注 / 被关注数、关注按钮(互关、单向、未关注三态)、他的帖子(按可见性过滤后);**右上角「⋯」菜单**:发书信(接书信的私聊请求规则)、举报此人;前世账号的「已转世」态。
7. **我的主页**:自己的帖子(含待审 / 已隐藏标记)、关注与被关注列表。
8. **举报**:选原因、补充说明、提交后的确认;对帖子、评论、用户三种入口。
9. **搜索**:本文明内按显示名或完整编号;「未找到」统一一种说法(不区分原因)。

## 文案

三种界面语言：简体中文、English、egy。egy 必须遵守 `灵魂簿 egy 词表.dc.html` 的全部定稿规则(六张词根表 + 小词，一词一义;否定 Nen、完成后置 Seth、每词首字母大写、无撇号;审核域已定:隐藏 Imen、删除 Fekh、通过 Menkh、禁言 Gerh、敏感词 Medu Djeseru、朋友圈 Shemsu、举报 Sedjem、评论 Wesheb、帖子 Medu;Sethet 只表技术错误;加载一律 Ini 等)。需要新词单列「新增词」并说明词义。
文案表放画布末尾，四列：键 / 中文 / English / egy,键名用 `soul_app.circle.*` 前缀。
