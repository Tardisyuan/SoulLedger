# 给 Claude Design 的 prompt ⑧:灵魂簿 App · 我的受刑

请在项目「灵魂簿」里新开画布 `灵魂簿 App · 受刑.dc.html`,为灵魂端 App 设计「我的受刑」这一块。视觉语言、字体、暗色主题、各文明 ink 配色、底部四个标签(本世 / 前世 / 转生 / 书信)、徽章与分区样式一律沿用 `灵魂簿 App.dc.html` 与 `灵魂簿 App · 聊天.dc.html`;iOS 与 Android 各出关键屏。

## 背景(后端已上线，按真实状态设计)

一个灵魂一世受审之后，会得到一份**受刑计划**:按顺序排好的若干「站」。第 1 站在原属文明，后面的站可能在别的文明(由联合审判定下)。每站有:文明、界域、刑期(或永久)、状态。灵魂一站一站地服刑，被调往外地时就是「暂居」;全部服完才能申请转生。

灵魂能看到(Q10):**全部站和各自的处置**(文明、界域、刑期或永久、状态)。**看不到**:理由、判官、别人提出的请求。

## 需要设计的屏与状态

1. **入口与位置**:放在「本世」页里(推荐一块卡片或分区)还是单独一屏?请给建议并画出。它要和本世页已有的「暂居 X · 原属 Y」提示合并考虑 —— 外地的站要不要随当地文明换 ink 皮肤。
2. **站的列表**:当前所在站要醒目;已完成、未开始、进行中要一眼分清。后端的节点状态有 9 种(待开始、调拨中、服刑中、等待、已完成、中止、已作废、永久、已撤销等),请决定哪些对灵魂**合并显示**(灵魂不需要知道「调拨中」和「待开始」的区别吗?),给出合并表。
3. **计划的几种整体状态**,各画一屏:
   - 进行中(在原属地 / 在外地服刑);
   - **在原属地，下一站尚未开始**;
   - **刑满暂留 · 等待重审结案**(外地刑期已满，但原属地有新审判未结，暂留原地);
   - **永久刑期**(停在某站，不再推进);
   - **已撤销(赦免)**:剩余刑期被赦免，视同完成;
   - **全部完成，可以申请转生**(给去「转生」的入口)。
4. **转生申请的拒绝提示**:受刑未完时在「转生」页点申请，后端答 `sentence_in_progress`。怎么提示?要不要一键带去「我的受刑」?
5. **四种推送的落地**:`sentence_completed`(全部服完)、`sentence_waiting`(刑满暂留)、`sentence_amended`(计划被改)、`sentence_pardoned`(被赦免)。点开后落到哪里、要不要高亮变化的那一站(沿用申请详情与书信的落地高亮:3px 竖条 +「新」小标)。

## 文案

三种界面语言：简体中文、English、egy。egy 必须遵守 `灵魂簿 egy 词表.dc.html` 的定稿规则(六张词根表 + 小词，一词一义;否定 Nen、完成后置 Seth、每词首字母大写、无撇号;Sethet 只表技术错误、Seshem 只表推进、加载一律 Ini 等)。需要新词请单列「新增词」并说明词义。
文案表放画布末尾，四列：键 / 中文 / English / egy,键名用 `soul_app.sentence.*` 前缀。

## 交付

关键屏 iOS / Android 各一版;上面每个状态一屏;节点状态合并表;文案表。不需要写代码。
