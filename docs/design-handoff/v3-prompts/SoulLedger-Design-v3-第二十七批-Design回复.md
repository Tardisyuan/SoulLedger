## 一、内容筛查提示(两组共用)

官员台和灵魂 App 用同一组 egy。`social.screening.*` 和 `soul_app.circle.screening.*` 后缀相同的两条，写法也相同。

| key 后缀 | 中文 | egy(最终) |
|---|---|---|
| masked | 已发布。部分内容已被替换。 | **Per Seth Er Neb. Medu Nedjes Iri Ky Seth.** |
| pending_review | 已发出,正在审核。审核通过前只有你看得到。 | **Per Seth; Em Wedja. Er Hesy: Djes-Ek Wa Maa.** |
| hidden | 这条内容没有通过筛查,已被隐藏。 | **Nen Shesep Em Maat Djes-Ef; Imen Seth.** |

- **发布 = Per Seth Er Neb**(发给所有人),**发出 = Per Seth**。同 `Nen Per`(没能发出)。两条的区别靠 Er Neb:打码的那条大家都看得到，送审的那条还没给别人看。
- **审核 = Wedja**,同第十批「Wedja 在工作流里表示审批」。**Em Wedja** = 正在审核。
- **通过前 = Er Hesy**(直到批准);Hesy 同批准。
- **只有你看得到 = Djes-Ek Wa Maa**。Djes-Ek 同 `batch.skipped_note`;不写 Maa Wa,那是「只读」。
- **筛查 = Maat Djes-Ef**,同第二十一批。**没有通过 = Nen Shesep**(没有被接受)。
- **隐藏 = Imen**,同第十批 `Medu Imen`(Imen 意为隐藏)。
- **替换 = Iri Ky**(改成别的),由已登记的 Iri + Ky 组成。不用 Imen:那是「隐藏」,和 hidden 撞车。不用 Iri Mawy:那是「更新」。
- **部分内容 = Medu Nedjes**(一小部分字);Nedjes 同 `Ankh Nedjes`。

## 三、移交状态

| key | 中文 | egy(最终) |
|---|---|---|
| officer_app.dispatch_status.waiting | 等对方批准 | **Per Ky: Nen Hesy Djer** |
| officer_app.dispatch_status.approved | 对方已批准 | **Per Ky: Hesy Seth** |
| officer_app.dispatch_status.rejected | 对方已驳回 | **Per Ky: Khesef Seth** |
| officer_app.dispatch_status.reason | 理由:{{reason}} | **Khet: {{reason}}** |

- **对方 = Per Ky**(另一个殿),由已登记的 Per + Ky 组成。不用 Per Hemes Setep Seth:移交的对方不一定是执行地。
- 三条都以 Per Ky 开头，读屏时先听到是谁。「Nen … Djer」= 还没，同 `Nen Shesep Djer`。批准 Hesy、驳回 Khesef,同第十批。
- **理由 = Khet**。第十九批是 Khet + 动词;这一行驳回、取消都会用到，所以不跟动词，单用 Khet 加冒号。`{{reason}}` 原样保留。
