## A. 全局导航壳（这轮最重要，不做就没法往下铺）

**现状：第二、三轮的审判台只有身份带，没有任何全局导航。** 从审判台走不到其余 44 个 Web 页面。整个产品是 **45 个 Web 页面 + 12 个 App 屏幕**，需要一个所有页面共用的壳。

Web 页面按这八组划分：

| 组 | 页面 |
|---|---|
| 入口 | 登录、欢迎页、仪表盘、个人资料、通知、关于 / 致谢 |
| 审判 | 审判列表、审判队列、审判台、跨殿审判（列表 / 详情） |
| 灵魂 | 灵魂列表、灵魂详情、功过总账 |
| 处置与受刑 | 处置、受刑申请、转生申请 |
| 调派与流程 | 调派（列表 / 详情 / 提案）、审批流（列表 / 编辑器） |
| 界域 | 界域拓扑、律条语料 |
| 灵魂端运营 | 书信收件箱、朋友圈（动态 / 详情 / 关注 / 个人页）、朋友圈审核、灵魂账号凭证 |
| 管理 | 用户、组织、租户、权限矩阵、菜单与按钮权限、角色 / 神祇、定时任务、审计日志、死亡同步、回收站、统计、助手管理 |

导航壳要回答这些：

1. **形态**：竖向、横向还是混合？分组怎么表达？二级项怎么展开？
2. **和身份带的关系**：导航是中性的，还是当前项也跟文明色走？身份带滚动后收成 48px 时，导航在哪、是否也收起？
3. **长标签**：埃及语最长的菜单项 `Sekhem Tepy Em Djeret` 是 21 个字符，页题 `Djadjat En Maat (42 Netjeru)` 是 28 个。导航和标题都要放得下，请画出埃及语版本。
4. **393 宽的降级**：底栏、抽屉，还是别的？
5. **面包屑 / 返回**：从队列进审判台再回来，路径怎么表达。
6. **当前项、悬停、焦点、禁用**四种状态。

**交付**：1440 浅色 + 深色、393，导航展开与收起两态，埃及语版本一张。

## B. 交互与动效规范

分四部分写。

### B1. 动效令牌

- **时长档位**：给具体毫秒数，说明每一档用在哪（例如 即时反馈 / 局部状态变化 / 布局转场 / 整页转场）。
- **缓动曲线**：给具体 `cubic-bezier(...)` 值，不要只写 "ease-out"。进场和出场用不同曲线。
- **位移距离**：淡入时位移多少像素。
- **可以动的属性**：优先 `transform` 和 `opacity`。用到 `height`、`width`、`top` 这类会触发重排的属性时单独说明为什么。

### B2. 逐个交互的规格

每一条写清五件事：**触发 → 哪些属性变 → 时长 → 缓动 → 减少动态效果下是什么样**。

必须覆盖：

**审判台**
- 按 1–4 选择判决（中央判决区的字形和文字替换）
- 按 F 展开全案 / Esc 返回聚焦 —— 判决区从中央收到右侧窄栏，资料舱铺开成三列。**这是整个产品最难的一次布局转场，请单独详细画。**
- 资料舱切换标签
- 盖印确认三步：进入确认层 → 印落下 → 结果状态
- 草稿保存的提示

**审判队列**（后端已有的七个动作，都要画）
- 上下键选行、Enter 打开
- C 认领 / 取消认领
- S 延后、本次会话延后、R 全部放回
- 改派（弹层 + 选择接手的判官）
- 「我认领的」分组切换
- 批量选择与批量操作条的出现

**通用**
- 页面之间切换
- 弹窗、抽屉、底部抽屉的进出
- Toast 出现与消失
- 骨架屏 → 内容
- 表格排序、表头吸顶、行展开
- 输入名称才能确认的危险操作；失败 Toast

**App**
- 底部四个标签切换
- 分节展开 / 折叠
- 「问一问」底部抽屉（打开、关闭、下拉关闭）
- 下拉刷新
- 离线条出现与消失（它会把页面内容推下去）
- 冷启动：空印框 → 印落框

**焦点与键盘**
- 焦点环什么时候出现（`:focus-visible`，不是 `:focus`）
- 键盘操作时不要播放鼠标悬停的动效
- 选中项滚动进视野时怎么动

### B3. 减少动态效果

不要只写「全部置 0」。逐类说明：哪些改成瞬时切换、哪些保留一个极短的淡入以免闪烁、哪些换成静态替代（例如骨架屏不做呼吸）。

### B4. 不要做的动效

请明确列出并说明理由。至少包括：装饰性循环动画、超过 3 个元素的入场瀑布流、弹跳与回弹（和「庄重」的气质冲突）、视差、数字滚动计数。

### B5. 技术约束（只写规格，不要推荐库）

已经装好的：

- **Web：GSAP 3.15**（`frontend/package.json`），加上 CSS 过渡。
- **App：React Native 内置的 `Animated` API**。

**没有装**：Reanimated、Gesture Handler、@gorhom/bottom-sheet、expo-haptics，以及任何 Web 动画库（framer-motion / motion 都没有）。

所以：

- 不要推荐新库，写规格就行。
- App 的手势（例如抽屉下拉关闭）请按 RN 内置 `PanResponder` 能做到的程度写。做不到的单独列出来，标「需要新增依赖」。
- 触觉反馈（haptics）没装。要用就标「需要新增依赖」，不要直接写进规格。

## C. 令牌表

一张能直接转成 CSS 变量的表。每个值给**名字 + 值 + 用在哪**：

- 颜色：浅色和深色两套 × （中性色 + 四个文明色）
- 字阶与行高
- 间距
- 圆角
- 阴影 / 层次
- 动效时长与缓动曲线
- z-index 层级
- 断点

对比度请给实测值，标出是否达到 4.5:1（文字）和 3:1（图形）。

## D. 两个新样板页

审判队列和灵魂详情。它们是检验导航壳和交互规范最合适的两页：队列是键盘密集型，灵魂详情是信息密集型。

**队列可以用的真实数据**：案号、灵魂姓名、所属殿、功分与过分、当前判决草稿、认领人、认领时间、延后时间与理由、第几世、审判种类。

**灵魂详情可以用的真实数据**：姓名、生卒年月日（可能不全）、籍贯、本名、生平描述、功分、过分、前世带来的功与过、当前状态、这个灵魂的全部审判与功过记录。

**仍然不要画**（后端没有这些字段）：候审天数、即将超时、案卷完整度、排名与百分位、预计完成时间。
