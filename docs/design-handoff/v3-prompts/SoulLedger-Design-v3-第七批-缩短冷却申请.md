# SoulLedger · 规范 v3 · 给 Design 的第七批：缩短冷却申请(2026-10-08)

转生申请被终局驳回后，灵魂进入一段冷却期（天数是每个殿的设置）。新功能（用户决定）：**冷却期内的灵魂可以申请缩短本次冷却，官员批准或驳回。** 两端都已按现有组件落地，这一批请 Design 在此基础上细化，不改流程。

请用本项目已同步的 v3 组件和令牌。App 出 393 浅色 / 深色；官员台出 1440 浅色、1440 深色、393 三档。

## 一、规则（已定，不改）

- 只有被「冷却」这一种原因拒绝的灵魂能申请；其他原因（审理中、已批准、受刑未完……）不出现入口。
- **每段冷却只能申请一次**，与「每份申请只能申诉一次」同形：驳回后这段冷却不能再申请，下一次冷却才有新的一次机会。同时只有一份待决。
- 批准时官员填「自今日起还需等待的天数」，须小于当时的剩余天数；零表示立即可以重新申请。驳回必须写给灵魂看的说明。
- 批准只提前这一段冷却的截止，**殿的冷却天数设置不变**。
- 结果推送给灵魂（与转生结果同一类别），锁屏文案不含新截止日期与驳回理由。

## 二、App（灵魂端）

位置：「转生申请」页，资格卡（禁用的「提交转生申请」按钮 + 「驳回后的冷却期内不能重新申请」+ 「冷却期至 {日期}」）的**下方**，同一张卡内。

状态（自上而下只出现其一，加一个入口）：

1. **可申请**：一枚次要按钮「申请缩短冷却」。
2. **表单**（点按钮后在原地展开，沿用申诉块的形状）：小标题「申请缩短冷却」，提示「冷却期内可申请一次缩短，由原属文明决定。」，一个多行输入「申请理由」（必填），一枚「提交申请」。提交成功后 toast「申请已提交」，表单收起，卡片刷新为状态 3。
3. **待决定**：一行说明文字「缩短冷却申请待决定」，没有按钮。
4. **已批准**：「缩短冷却申请已批准，冷却期至 {新日期}」——日期就是资格卡上「冷却期至」的那个（已经提前），两处数值相同。没有按钮。
5. **已驳回**：「缩短冷却申请被驳回」，下一行「说明：{官员的说明}」。没有按钮（这段冷却不能再申请）。

请给出：这五种状态在卡内的层级与间距；「已批准」时资格卡上「冷却期至」要不要有一个「已提前」的标记；推送落地时（打开 App 落在转生申请页）要不要高亮这一块。

## 三、官员台

位置：`/rebirth-applications` 页头加两个页签「转生申请 / 缩短冷却申请」（审判队列同一种下划线页签）。第二个页签是同一种表：

- 列：灵魂（名 + 编号）、第几世、剩余冷却（「N 天」；冷却已结束写「冷却已结束」）、状态徽章（待决定 / 已批准 / 已驳回）、提交于、「查看详情」。
- 筛选签：全部 / 待决定 / 已批准 / 已驳回。
- 详情对话框：编号、第几世、状态、冷却截止、剩余冷却、（已批准时）批准后剩余天数、（已决定时）决定人 · 时间、提交于；下方「申请理由」正文；有说明时「给灵魂的说明」正文。
- **决定区**（只在待决且冷却未结束、且当前用户有流程批准权限时出现）：数字输入「自今日起还需等待（天）」+ 提示「须小于剩余 N 天；0 表示立即可以重新申请」；多行输入「给灵魂的说明」+ 提示「驳回必须填写；灵魂会读到」；两枚按钮「批准」（主）「驳回」（次）。本地先校验天数与说明，服务端拒绝时 toast 给原因（已经决定过了 / 冷却已结束 / 天数不合法 / 驳回须写说明）。

请给出：剩余冷却这一列要不要改成进度（已过 / 总长）；「冷却已结束」的待决行是否要灰掉；决定区两枚按钮的排布与说明输入是否要在驳回时才强制。

## 四、必须保留

- 入口只在冷却拒绝下出现；每段冷却一次。
- App 表单与申诉块同形；官员台与转生申请同一种表与对话框。
- 三种语言的文案已在语言包里（`soul_app.cooldown.*`、`soul_accounts.cooldown.*`、`soul_push.cooldown_shortening_*`）；egy 全部用既有词根，没有新词。
