# 第十五批 · 补充：盘点出来、还没有稿的功能块(2026-10-10)

上一份(第十五批)只列了已经做出来的 5 处和 2 处等稿的。这一份是 2026-10-10 全量盘点里其余没有稿的功能块，共 9 处。
结论先说：49 个页面没有整页缺失，也没有占位页；缺的都是页面里的一块。

分三组：A 正在做、先按现有组件搭了，请审；B 后端已有、前端没有界面，请画；C 全站都没有的通用能力，请定要不要、要的话画。

每一处请回：照现在 / 改哪里(写规格即可) / 需要画稿。egy 文案等界面定了再一起给。

---

## A. 正在做，先按现有组件搭，请审(3 处)

**A1. Web 权限页 · 导出配置 / 导入配置。**
后端早就有，前端一直没有入口。现在在权限页加两个入口：
- 导出：直接下载一个文件，文件名带殿名和日期。
- 导入：选文件 → 显示「将要导入多少条」的摘要 → 确认 → 显示结果(新增 / 更新 / 跳过各多少)。
这一版只做「合并」，不提供「覆盖」(覆盖会删掉文件里没有的权限行，包括管理员自己的，产品还没定)。
请看：两个入口放在权限页的哪里(工具条 / 更多菜单)；导入的三步用一个弹层还是抽屉；摘要和结果怎么排；如果以后要加「覆盖」，危险提示怎么写怎么放。

**A2. 两个 App · 「需要更新」整屏。**
App 版本低于后端要求的最低版本时，整屏拦住，只有一个按钮去商店更新；未登录也拦。不做「有新版本」的软提示。
现在用各自 App 现有的整屏状态样式。
请看：这一屏的版式、文案语气(灵魂端与官员端要不要不同)、要不要放品牌印记。

**A3. 两个 App · 出错整屏。**
接入崩溃上报的同时加了根级的出错兜底：界面渲染出错时不再白屏，显示一屏「出了点问题」加「重试」。
请看：版式与文案；要不要告诉用户「已自动上报」。

## B. 后端已有，前端没有界面，请画(3 处)

**B1. Web 仪表盘 · 「数据截至」。**
你的仪表盘稿上有「数据截至 ……」，代码里没有写，因为接口当时没有这个值。后端可以补。
请确认：位置与格式照原稿不变？统计是实时算的时候写什么(「刚刚」/ 具体时间 / 不显示)？

**B2. Web 灵魂详情页 · 右栏案号。**
稿上右栏有案号。案号属于某一场审判，而一个灵魂可以有多场，所以当时没写。
请定：右栏显示哪一个(最近一场 / 当前未结的一场)，还是列出全部并可点进审判详情；没有审判时显示什么。

**B3. 官员 App · 派遣(移交)审批入口。**
App 里批准 / 驳回移交的逻辑有，但「待办」四类里没有「移交」这一类，只能从推送点进去。
请定：待办里要不要加第五类「移交」；和上一份里你建议的「待回书信」放在一起时，五六组的顺序怎么排。

## C. 全站都没有的通用能力，请定要不要(3 处)

**C1. 打印。**
全站没有打印样式。最可能需要的是判词(审判结案后的文书)、受刑计划、灵魂档案。
请定：哪几页需要打印；打印版式(页眉的殿名与印、页脚的案号与页码、是否去掉侧栏与按钮)；要不要「打印」按钮还是只靠浏览器菜单。

**C2. 更多列表的批量操作。**
现在只有灵魂、用户、审判认领有批量条(选中后底部出现)。移交、处置、通知列表没有。
请定：这三个列表各自需要哪些批量动作(通知：全部已读 / 删除；移交：批量批准 / 驳回？处置：?)；不需要的直接说不要。

**C3. 更多列表的导出。**
现在能导出的：灵魂 CSV、账簿统计与流水、审计日志。移交、处置、跨殿审判没有。
请定：这三处要不要导出；入口放在哪里(与现有导出一致即可的话回「照灵魂列表」)。
