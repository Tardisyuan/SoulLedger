# SoulLedger 灵魂簿 · 第五轮：修聚焦视图 + 四档宽度 + 组件库

第四轮的导航壳、交互规范、令牌表和两个新样板页都收下了，方向不变。这一轮三件事：修一个布局缺陷、把宽度档位补齐、出组件库。

## A. 修：导航展开时，聚焦视图放不下

### 现象

导航栏展开时，审判台的聚焦视图被挤，中央判决区明显变窄。

### 从 `index.css` 算出来的原因

```css
.delivery-layout { grid-template-columns: minmax(960px,1fr) 225px; gap: 22px; padding: 22px; }
.web-shell       { grid-template-columns: 252px minmax(0,1fr); }
.web-shell.shell-collapsed { grid-template-columns: 68px minmax(0,1fr); }
.focus-stage     { grid-template-columns: 220px minmax(430px,670px) 240px;
                   gap: clamp(30px,4vw,70px); padding: 38px 35px; }
```

聚焦视图要放下自己，至少需要：

```
220 + 430 + 240  = 890   （三列的最小值）
+ 2 × gap                （gap 是 clamp(30,4vw,70)）
+ 35 × 2         = 70    （左右内边距）
```

在 1440 宽的浏览器里 `4vw` = 57.6，于是最小需要 **1075px**。而导航展开时，内容区只有 `1440 − 252 = 1188px`。放得下，但中间那列只剩 `1188 − 220 − 240 − 115 − 70 = 543px`，离它的上限 670 少了 19%。**中央判决是这一页唯一的焦点，导航一开它就缩水。**

窗口再窄一点就直接放不下了。`.desktop-artboard` 是 `overflow:auto`，所以会出现横向滚动条；`.web-shell` 是 `overflow:hidden`，还可能裁掉内容。

### 三个需要一起修的问题

**1. `1440` 这个按钮并没有把画板设成 1440 宽。**
`.delivery-layout` 的第一列是 `minmax(960px,1fr)`，画板宽度实际上跟着浏览器窗口走。在一台 1512 宽的笔记本上，画板约 `1512 − 225 − 22 − 44 = 1221px`，不是 1440。所以现在看到的每一张「1440」都不是 1440。**请把画板宽度真的钉死**（例如 `width:1440px` 再整体缩放），否则所有断点规则都验证不了。

**2. `gap: clamp(30px,4vw,70px)` 里的 `4vw` 量的是浏览器视口，不是画板。**
列宽跟着画板走，间距跟着窗口走，两者对不上。请改成固定值，或者用容器查询（`cqw`）。

**3. 这条本来能挡住问题的规则是死的：**

```css
.desktop-artboard > .judgment-product { min-width: 1080px }
```

`.judgment-product` 不是 `.desktop-artboard` 的直接子元素——中间隔着 `.web-shell` 和 `.shell-content`，所以这条选择器从来没有生效过。请把下限放在真正承载工作台的那个元素上。

### 要求

导航展开、1440 宽的情况下，中央判决列不得小于 **600px**。做不到就改设计：把三列的固定侧栏改成可收起，或者在导航展开时自动收起一侧。**请说明你选了哪种，以及理由。**

## B. 宽度档位：从 2 档补到 4 档

令牌表里已经写了四个断点，但评审控件只有 `1440` 和 `393` 两个，`768` 和 `1024` 从来没被画出来过——也就是说这两档的规则没有任何东西验证过。

请把切换器改成四档，每一档都真的渲染，并且画板是那个真实宽度：

| 档位 | 名字 | 导航形态 | 必须验证 |
|---|---|---|---|
| **1440** | wide | 竖向分组导航展开 | 聚焦视图三列 + 全案视图三列都放得下（见 A） |
| **1024** | tablet | 导航收起成 68px 图标条 | 聚焦视图还剩多少；全案视图三列是否要降成两列 |
| **768** | compact | 底栏 + 「更多」抽屉 | 工作台怎么单列化；全案视图在这一档还存不存在 |
| **393** | phone | 五项底栏 + 「更多」抽屉 | 现状 |

每一档都要出：审判台（聚焦）、审判队列、灵魂详情，浅色即可；深色只出 1440 和 393。

**请顺带说清两件事：**

1. **每一档之间是怎么过渡的。** 断点是硬切换，还是在区间内有流式伸缩？
2. **1024 和 768 之间谁负责收起导航。** 现在令牌表写的是 1024 收起、768 变底栏，请在图上确认这个分界合理。

## C. 组件库

**重要背景：这套设计会整体替换掉现有的实现，不是新增一层皮。** 全部 45 个 Web 页面和 12 个 App 屏幕都要换过来。

所以下一步的关键不是再画几十张页面稿，而是**一套组件库**——页面我们按组件在代码里铺，这条路上一版走通过。

请按下面的清单出组件规范。每个组件给：全部状态、尺寸、间距、浅色与深色、焦点态、禁用态、以及动效（引用第四轮的时长与曲线令牌，不要另起一套）。

**表单与动作**
- 按钮：主要 / 次要 / 危险 / 幽灵 × 默认、悬停、按下、焦点、禁用、加载中
- 输入框、文本域、下拉选择、搜索选择（可搜的下拉）、筛选标签
- 三种尺寸，以及带错误提示时的样子

**数据展示**
- 表格：表头、排序态、表头吸顶、行悬停、行选中、批量操作条、空表、加载中
- 树形行（界域拓扑、权限矩阵用）
- 分页
- 徽章：灵魂状态六种（○ 在世、◇ 审判中、▣ 已处置、↻ 轮回中、≡ 已终结、◌ 迷失）、判决四种（✓ 通过、✕ 不过、◇ 待定、↺ 重审）
- 图表：灵魂状态用冷灰蓝明度梯度，去向用四种图案，不用彩色分类

**层与反馈**
- 弹窗、抽屉（右侧）、底部抽屉（App）
- Toast：成功、失败、信息
- 空状态、骨架屏
- 出错页：403 / 404 / 500
- 离线提示条

**导航**
- 标签页、面包屑、图标选择器

**危险操作**
- 不可撤回且要输入名称的确认框（红色实底按钮）
- 不可撤回但无名称可输的确认框（普通确认）
- 可撤回的操作（橙色警示按钮，例如移入回收站）

## D. 仍然要守住的约束

1. 判决和灵魂状态一律「字形 + 文字」，**不用红绿等状态色**。冷玫红只给「操作失败 / 系统出错」，橙色只给「可撤回的危险操作」。
2. 文明色只出现在第四轮文明规范页列出的那几处。组件库整体是中性的。
3. 三种界面语言：简体中文、English、古埃及语转写。最长页题 `Djadjat En Maat (42 Netjeru)` 28 字符，最长菜单项 `Sekhem Tepy Em Djeret` 21 字符。
4. 文字对比度 ≥ 4.5:1，图形 ≥ 3:1；焦点清楚可见；支持「减少动态效果」。
5. 产品界面没有低于 11px 的文字。可点击区域不低于 44 × 44。
6. 不要编造后端没有的字段：候审天数、即将超时、案卷完整度、排名、百分位、预计完成时间。
