# 第五十批 · 灵魂「失踪」与「召回」(2026-10-24)

## 背景

灵魂状态里一直有 LOST(失踪)：处置已定、押送去处途中走失。状态机允许「已处置 → 失踪」,但界面上没有任何入口，也没有出口。
用户定了：做最小的进出口，不做追捕流程。

- **标记失踪**:灵魂处于「已处置」(DISPOSED)时，官员可标为失踪，**必须写原因**。
- **召回**:灵魂处于「失踪」时，官员可召回，回到「已处置」(继续押送),**必须写原因**。
- 两次操作都进灵魂事件时间线(状态变更，带原因)和审计日志。
- 权限：能做状态变更的官员(`soul.transition`)。后端已上线(`POST /souls/{id}/transition/`,缺原因时 400 `reason_required`)。

## 要的(Web 灵魂详情页)

1. 入口放在哪里：灵魂详情页现有的操作区 / 「更多」菜单，你定。只在对应状态出现(已处置时「标记失踪」,失踪时「召回」)。
2. 弹层：标题、一句说明后果、原因输入框(必填，最多 500 字)、确认 / 取消。标记失踪是否用危险色，你定。
3. 失踪状态的呈现：身份带 / 状态徽章上「失踪」怎么显示(徽章字形与色，和其他六个状态一套)。
4. 时间线上这两条事件的写法(标记失踪、召回，各带原因)。

## 文案

请给 zh-Hans / en / egy(egy 只用词表里已有的词，没有的写进待补):

| 键 | 用途 |
|---|---|
| `souls.lost.mark` | 按钮「标记失踪」 |
| `souls.lost.mark_title` / `souls.lost.mark_body` | 标记弹层标题 / 说明 |
| `souls.lost.recall` | 按钮「召回」 |
| `souls.lost.recall_title` / `souls.lost.recall_body` | 召回弹层标题 / 说明 |
| `souls.lost.reason_label` / `souls.lost.reason_required` | 原因输入框标签 / 未填时的提示 |
| `souls.lost.marked_toast` / `souls.lost.recalled_toast` | 成功提示 |

官员 App 本批只读：灵魂详情显示「失踪」状态即可，不做操作入口。若你认为官员 App 也该能标记 / 召回，请说明。
