对照同类产品查了一遍缺口,下面十四项都还没做,前后端也都没动。请先出稿和文案,我们按稿做。
每项后面标了我们估的工作量(小 / 中 / 大)。**不必一次全画**:请先回答第一节的排序问题,再按你认为合理的顺序分批出。

沿用的东西不再重复:v3 的令牌、393 宽的 App 版式、方角、四种文明的气质色、三种界面语言(zh / en / egy)。

## 二、官员台(Web)

### W1 · 列的显示偏好(小)
- **现状**:列表页用同一个表格组件,列是固定的。灵魂列表已经会记住筛选和排序(记在这台浏览器里),但不能隐藏列。
- **要画**:列菜单的入口放在哪(表头右端 / 筛选条上)、菜单本身(勾选显示哪些列、恢复默认)、哪些列不允许隐藏。
- **请定**:偏好是每个列表各记一份,还是全站一份;393 宽下列表是「角色优先」的卡片排法,列菜单在那里还出不出现。

### W2 · 登录设备列表(中)
- **现状**:官员改密码会让其他设备全部退出;除此之外看不到自己在哪些设备上登录,也不能单独让某一台退出。个人中心现在有:基本信息、修改密码、邮件通知、两步验证。
- **要画**:个人中心里的「登录设备」一节:每台设备显示什么(设备与浏览器、上次活动时间、大致位置要不要、是否「这台」)、单独「退出这台」、「退出其他全部」。
- **请定**:退出某一台要不要再输密码;「这台」能不能在这里退出;两步验证的「30 天内不再询问」设备是否并进同一张表。

### W3 · 通知按类别静音(中)
- **现状**:个人中心只有一个「邮件通知」总开关。站内通知页只有「全部标记已读」。
- **要画**:按类别的开关表。类别我们现有的是:待审批、审批超时、改派请求、密码求助、移交(提出 / 批准 / 驳回 / 取消)、书信交接。每类分「站内」和「邮件」两列。
- **请定**:哪些类别不允许关(例如安全相关);放在个人中心还是通知页的齿轮里。

### W4 · 案卷与审批的附件(大)
- **现状**:审判页有评议区和审判评语,只有文字。书信和朋友圈已经能发图(私有上传、签名取图)。
- **要画**:附件区在案卷页的位置;上传中 / 失败 / 超限的状态;列表里一个附件显示什么(名称、大小、上传人、时间);预览与下载;删除。
- **请定**:允许的类型(只图片与 PDF?)、单个与总量上限的写法、谁能删(上传人 / 殿主 / 管理员)、打印卷宗时附件怎么体现。

### W5 · 案卷与审批流的导出(中)
- **现状**:审计日志、灵魂、功过、处置、移交已有 CSV 导出;案卷(审判)和审批流没有。
- **要画**:导出入口的位置与文案;请沿用现有导出按钮的样式,只需确认这两页放在哪、导出范围怎么说(「按当前筛选」)。

### W6 · 带审计的模拟登录(中)
- **现状**:没有。管理员排查「某官员看不到某个菜单」时只能让对方截图。
- **要画**:用户管理里「以此人身份查看」的入口与确认弹层(要填理由);进入后**全程可见**的顶部提示条(正在以谁的身份、退出按钮);审计里这类记录怎么显示。
- **请定**:模拟期间是否只读(我们倾向只读);哪些角色能发起;被模拟的人要不要收到通知。

## 三、灵魂 App

### S1 · 登录设备与登录历史(中)
- **现状**:设置 › 账号安全现有三行:修改密码、两步验证、面容 / 指纹登录(只在这部手机上)。灵魂看不到自己的账号在哪登录过。
- **要画**:账号安全里的第四行与它的子页:设备列表(这部手机 / 其他)、最近的登录记录(时间、方式:密码 / 面容 / 恢复码、成功或失败)、让某台设备退出。
- **请定**:记录保留多久怎么对用户说;失败的登录要不要显示;看到陌生设备时页面给什么下一步(改密码的入口)。

### S2 · 应用锁:切回前台要求解锁(小,**可选**)
- **现状**:面容 / 指纹只用于登录。App 放到后台再回来不会锁。
- **说明**:产品的意见是「这应该是用户自己开了才有的东西」,排在最后。如果你也认为该做,请画:设置里的开关(与「面容登录」是什么关系)、多久算超时、锁屏那一屏、认不出时退回输密码。如果认为不必单独做,请直说。

### S3 · 个人数据导出(中)
- **现状**:没有。账号注销已定为不做。
- **要画**:设置里的入口、导出包含什么的说明、申请后等待与完成的状态、文件怎么交到手里(系统分享面板)。
- **请定**:是立即生成还是排队;导出要不要先输密码。

### S4 · 字号设置(小)
- **现状**:App 不跟随系统字号,也没有自己的设置。
- **要画**:设置里的字号行与选择页(几档、预览一段示例文字)。
- **请定**:是跟随系统字号更好,还是 App 内自设;最大一档下哪些屏允许换行、哪些要保持一行(编号、时间)。

### S5 · 帮助与反馈入口(小)
- **现状**:没有。遇到问题只能找本殿官员。
- **要画**:设置里的入口;帮助页的结构(常见问题分几组);反馈表单(类别、文字、可选截图)和提交后的状态。
- **请定**:常见问题的条目请直接给出第一版(登录不了、忘记密码、手机丢了、交付单是什么、怎么联系本殿);反馈发到哪 —— 我们倾向落到殿司收件箱,和书信同一处处理。

## 四、官员 App

### O1 · 批准 / 驳回前的面容或指纹确认(小,要重建 App)
- **现状**:点批准或驳回会先弹确认弹层(写理由、看这次决定影响什么),确认后生效。没有生物识别。
- **要画**:确认弹层里多出来的这一步放在哪(点「确认」后弹系统验证);验证失败或取消后的样子;设置里的开关。
- **请定**:默认开还是关;是所有决定都要,还是只有不可逆的那几类;手机没有录入面容时怎么办。

### O2 · 待办按类型筛选(小)
- **现状**:待办页把五类事项排在一张表里(审批、会签、转生申请、缩短冷却申请、移交),只能按「我的 / 全部」分组。
- **要画**:筛选条(类型多选、数量角标)、筛选后为空的状态。

### O3 · 断网时的操作排队与读缓存(大)
- **现状**:断网时列表显示加载失败;已经修掉「断网被退回登录页」。灵魂 App 的书信有发件箱(断网排队、恢复后发出),官员 App 没有。
- **要画**:断网横条;列表在断网时显示上次的内容并标明时间;一条决定在「待发出」时在列表和详情里的样子;恢复后发出失败(例如别人已经处理了)怎么告诉官员。
- **请定**:哪些操作允许离线排队(我们倾向只允许回信,**不允许**离线批准 / 驳回,因为排队期间案卷状态可能变了)。
