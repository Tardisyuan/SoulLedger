# A8 · 全局搜索(Design 2026-10-03,Search.dc.html + v3-batch4-search-reply.md)

取自 Design 项目「SoulLedger v3」的 `templates/soulledger-v3-pages/`。下面先照抄 Design 的答复，再列从画面里读出的尺寸。

## Design 答复(原文)

### 1. 入口
- 快捷键：**同意 ⌘K / Ctrl K**。**`/` 不用**:律条和表单里常常在打字,`/` 要额外判断焦点，容易误触。
- 1440:顶栏右侧放一个**宽 240、高 36 的搜索框样按钮**(图标 + 「搜索」+ `⌘K` 键帽),不只放一个图标，否则没人知道有快捷键。顺序为 搜索 / 通知 / 头像。
- ≤768:顶栏右侧放 44×44 的搜索图标，在通知左边。点开是**全屏**页，不是弹层；不放进底栏。

### 2. 范围
- **四类**,顺序固定为 **案件 → 灵魂 → 律条 → 页面**。
- 「页面」= 当前用户菜单里的页面，在前端从已加载的菜单里筛，**不用接口**。
- 流程、调度、界域、神祇：这一版不加。

### 3. 结果界面
- **弹层(命令面板)**:宽 640,距顶 96,最高 560,遮罩与弹窗相同(scrim + scrim-alpha)。≤768 时全屏。
- 每类最多 **5 条**。超出时这一类底部给「查看全部 N 个灵魂 →」,跳到列表页并带上 `?q=`。律条跳语料阅读器的搜索。
- 行高：统一 48(律条两行 64),窄屏也是 48。
- 每条显示：
  - 案件：案号(等宽)· 灵魂姓名 · 殿 ……… 判决徽章
  - 灵魂：姓名 · 编号(等宽)· 文明 ……… 状态(○ ◇ ▣ ↻ ≡ + 文字)
  - 律条：出处 / 第二行条文摘录(衬线，一行省略，命中处居中)
  - 页面：菜单名 · 路径
- 命中字：加粗 600 + 下划线，**不用颜色**。
- 键盘：打开后焦点在输入框，第一条默认选中;↑↓ 跨类连续移动，到头不循环。
  - ↵ 打开：案件 `/judgment/:id`,灵魂 `/souls/:id`,律条 `/corpus?article=:id`(滚到该条),页面直接跳 path。
  - ⌘↵ / Ctrl↵:新标签页打开。
  - Esc 关闭，焦点回到入口按钮。
- 读屏：输入框 `role=combobox` + `aria-activedescendant`,结果是 `listbox`,每类一个 `group`。结果到达时用 live region 读出「案件 3 条，灵魂 12 条」。

### 4. 状态
- **还没输入**:列出最近打开的 5 条，按用户存在本地，各类混排、带类型。下面一行提示「案号要输完整」。没有记录时只显示这行提示。
- **正在搜索**:防抖 200ms,输入至少 1 个字。
  - 首次：每类 3 行骨架屏。
  - 之后：保留上一次的结果，输入框下面出一条 2px 进度条，结果区不闪。
  - 每类各自返回、各自显示，不等最慢的那一类。
- **没有结果**:衬线标题「没有找到「…」」,下面一行说明三类分别按什么字段搜。
- **某类没权限**:整类不出现，不提示。
- **某类请求失败**:这一类照样占位，显示「! 加载失败」(只这几个字用 `--color-danger`)、一句「其余几类不受影响」和「重试」按钮；其余几类照常显示。

### 5. 完整案号
- 照常列出，不自动跳。案件组排第一，这一条标「案号完全一致」并默认选中，按 ↵ 一下就到。

### 6. 动效
- 开：opacity 0→1,translateY −4→0,160ms,ease-enter。遮罩同步淡入 160ms ease-enter。输入框在第 0 帧拿到焦点。
- 关:opacity 1→0,80ms,ease-exit,不位移。
- 窄屏全屏：开 240ms ease-enter(从下 16 上滑)/ 关 160ms ease-exit。
- 减少动效：都瞬时。
- 顺带:普通弹窗的「关 180」建议改成 160。
