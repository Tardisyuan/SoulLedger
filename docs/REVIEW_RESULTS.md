# SoulLedger V2 规划审核结果

审核日期: 2026-05-27
审核模块: 死亡同步 API、WebSocket、数据隔离、抢购系统

---

## 一、死亡同步 API 审核

### 问题
1. **认证安全** - `sync_token` 放在请求体不安全，应统一用 `X-API-Key` header
2. **批量限制** - 无批次大小上限，建议≤100条
3. **性能** - 大批量应走 Celery 异步处理
4. **幂等性** - 缺少基于 `source_id` 去重机制
5. **加密** - `id_number` 明文传输，需加密

### 改进建议
> 1. 移除请求体中的 `sync_token`，统一用 `X-API-Key` header
> 2. 添加批次大小限制（≤100条）和异步处理
> 3. 定义完整错误响应格式（code/message/details）
> 4. 添加 `id_number` 加密传输和存储说明
> 5. 增加幂等性保障（基于 `source_id` 去重）

## 二、WebSocket 审核

### 问题
1. **认证** - JWT token 通过 query string 传递存在日志泄露风险
2. **通知类型** - 缺少系统公告、好友申请状态变更
3. **重连机制** - 缺少指数退避策略
4. **消息格式** - 无消息 ID（用于去重/ACK）
5. **性能** - 无连接数限制、无离线消息推送机制

### 改进建议
> 1. 改为 `ws://server/api/v1/ws/notifications/` + 单独 `token` header
> 2. 添加 `system_announcement`、`friend_request_status` 类型
> 3. 定义指数退避重连策略（1s, 2s, 4s, 8s, 16s）
> 4. 增加消息 ID 字段用于去重/ACK
> 5. 增加连接数限制和离线消息队列

---

## 三、数据隔离审核

### 问题（高风险）
1. **跨文明隔离** - `soul_friends` 表缺少 `civilization_id`，可导致跨文明数据泄露
2. **好友状态机** - 缺少 REJECTED/BLOCKED 状态
3. **朋友圈评论** - 需区分"根评论"和"回复"分别授权
4. **跨文明规则** - 三界灵魂能否互加好友/聊天完全未定义

### 改进建议
> 1. `soul_friends` 表必须加入 `civilization_id` 并在 API 层强制校验
> 2. 明确好友关系状态机：PENDING → ACTIVE / REJECTED / BLOCKED
> 3. 朋友圈评论需区分"根评论"和"回复"分别授权
> 4. 补充跨文明好友/聊天/名额的隔离规则

---

## 四、抢购系统审核

### 问题
1. **原子性** - 检查库存和 DECR 不是原子操作，并发下可能超卖
2. **异常处理** - Redis 扣减成功但 DB 写入失败时无回滚机制
3. **超时释放** - 抢购后超时未支付无释放机制
4. **限流** - 缺少用户级限流（一人只能抢购一次）
5. **防刷** - 无图形验证码/防脚本机制

### 改进建议
> 1. 使用 Lua 脚本保证检查+扣减原子性
> 2. 增加库存预热、异常回滚、超时释放机制
> 3. 补充用户级限流（Redis Set 记录已抢购用户）
> 4. 添加图形验证码防脚本
