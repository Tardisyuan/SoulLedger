# 语音助手接入(Siri / 小爱同学)可行性与计划

2026-10-09 起草。记忆和文档里都没有这件事的既有决定(过去的对话提到过，但没有落成结论)。
本文只写计划，不改代码。

## 0. 结论先说

**可行，但只适合做「查」和「打开」,不适合用语音做「批」。**

| 端 | 能做到的 | 代价 |
|---|---|---|
| iOS · Siri / 快捷指令 | 说一句话打开 App 的某一页;让 Siri 念出「有 N 件待你处理」 | 中:要写 Swift 原生模块 + 配置插件(Expo 57 没有现成的 App Intents 库) |
| Android · 桌面快捷方式 | 长按图标直达某一页 | 小:配置插件加 `shortcuts.xml` |
| Android · Google Assistant | 只能挂在谷歌预定义的意图上，自定义说法受限;中国大陆基本不可用 | 中，收益低 |
| 小爱同学 | 云端技能:用户对小爱说话 → 小米服务器调我们的后端 → 小爱念结果 | 大:要建 OAuth 授权服务、小米开发者账号与审核、境内可访问的 HTTPS 域名 |

你贴来的那段说明以「记一笔账」举例，是通用记账 App 的场景，和 SoulLedger 的业务对不上。下面按我们自己的两个 App 重新设计。

## 1. 做哪些语音动作

### 官员 App(灵魂簿 · 官员)
| 说法(示例) | 做什么 | 建议 |
|---|---|---|
| 「灵魂簿有几件待我处理」 | 念出待办总数，不念案件内容 | 做。和锁屏推送同一口径:只说数字 |
| 「打开灵魂簿待办」/「打开审判」 | 打开 App 落到对应页签 | 做 |
| 「批准 / 驳回某某」 | 语音直接审批 | **不做**:审批要两步验证、驳回必须写理由、操作不可撤回;语音的误识别和旁听风险都太大 |

### 灵魂端 App
| 说法(示例) | 做什么 | 建议 |
|---|---|---|
| 「我的冷却还剩几天」 | 念出剩余天数 | 做(只念给已登录的本人;锁屏下要求先解锁) |
| 「打开我的本世」/「打开书信」 | 打开到对应页 | 做 |
| 「问一问:……」 | 打开 App 的「问一问」并带入问题 | 可做，第二期 |
| 提交转生申请 / 缩短冷却申请 | — | **不做**:提交前要确认表单 |

## 2. 前置条件(两端共用)

1. **深链接**:两个 App 现在都没有配置 `scheme`,也没有处理链接打开(代码里没有 `Linking.getInitialURL` / `addEventListener`)。语音和桌面快捷方式「打开某一页」都靠它,所以第一步是给两个 App 加 scheme(如 `soulledger-officer://todo`)和路由。官员 App 现有的推送落地(按推送里的 `target` 打开条目)可以复用同一套路由。
2. **只读接口**:待办总数已有(`/officer-app/todo/` 的各组 count);冷却剩余天数可以由灵魂端已有的 `cooldown_until` 算出(App 的申请表现在就是这样算的)。不需要新接口。

## 3. iOS:App Intents

- **做法**:在 `mobile/` 和 `mobile-officer/` 各加一个本地 Expo 模块(Swift),定义 `AppIntent`,再用 `AppShortcutsProvider` 注册中文说法。用配置插件把 Swift 文件加进生成的 iOS 工程(和这次修 iOS 27 闪退的 `withSceneLifecycle` 同一种做法)。
- **「打开某页」**:Intent 设 `openAppWhenRun = true`,再通过深链接把要去的页面交给 JS。
- **「念出数字」**:有两种方案。
  - **A(推荐先做)**:JS 每次拉到待办数或冷却天数时，写进 App Group 共享存储;Intent 读这个缓存来念，并说明「截至 HH:MM」。不在原生侧发网络请求，也不碰登录令牌。
  - **B**:Intent 在原生侧用钥匙串里的令牌直接请求后端。数字实时，但要处理令牌刷新和两步验证，复杂得多。
- **隐私**:Intent 设 `authenticationPolicy = .requiresAuthentication`,锁屏时 Siri 要先解锁才会念;念的内容只有数字。
- **最低系统**:App Intents 要 iOS 16 及以上。我们模拟器实测用的是 iOS 27。

## 4. Android

- **桌面快捷方式**(长按图标出菜单):用配置插件生成 `res/xml/shortcuts.xml`,每一项是一个深链接。成本小，国内机型(包括小米)都支持。**建议和 iOS 第一期一起做。**
- **Google Assistant 的 App Actions**:只能对接谷歌预定义的意图类型，我们的「待办」「冷却」都套不上;中国大陆用户基本用不到。**不建议做。**

## 5. 小爱同学

- **能走的路**:小爱开放平台的「云端技能」。用户对小爱说话后，小米服务器把意图发到我们后端的 webhook,我们返回要播报的文字。App 本身不用改。
- **难点**(以下都**未核实**,要先查小米开放平台当前的接入文档):
  1. **账号关联**:小爱要知道「这个说话的人是哪个官员 / 哪个灵魂」,这需要 OAuth 2.0 授权(账号绑定)。我们现在没有 OAuth 授权服务，要新建(例如 django-oauth-toolkit),是一块安全敏感的新代码，还要配套两步验证。
  2. **主体与审核**:需要小米开发者账号，技能需要审核;webhook 很可能要求境内可访问、已备案的 HTTPS 域名。
  3. **能念什么**:同样只建议只读、只念数字。
- **建议**:放在最后，等账号关联的方案定下来、上线环境也定了再评估。

## 6. 分期

| 期 | 内容 | 依赖 |
|---|---|---|
| 一 | 两个 App 加 scheme 与深链接路由;Android 桌面快捷方式;iOS 「打开某页」类 Intent | 无 |
| 二 | iOS 「念出数字」(方案 A:App Group 缓存);灵魂端「问一问」带入问题 | 一期 |
| 三 | 小爱云端技能(OAuth 授权服务 + 技能审核) | 上线环境、小米开发者账号、你的决定 |

一、二期都在我们自己的代码里，可以照现在的方式派子代理做，在 iOS 和 Android 模拟器上验收(iOS 的 Siri 能在模拟器里用键盘输入测)。
